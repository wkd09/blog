# AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration

이 글은 논문 [AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration](https://arxiv.org/abs/2306.00978)을 바탕으로 정리한 글이다.

> Ji Lin, Jiaming Tang, Haotian Tang, Shang Yang, Wei-Ming Chen, Wei-Chen Wang, Guangxuan Xiao, Xingyu Dang, Chuang Gan, Song Han
> MLSys 2024 Best Paper Award. [[Paper](https://arxiv.org/pdf/2306.00978)] [[Code](https://github.com/mit-han-lab/llm-awq)]

논문의 핵심은 간단하다.

> LLM의 모든 weight가 똑같이 중요한 것은 아니다. activation이 큰 channel과 연결된 weight를 더 조심해서 양자화하면, 3-4bit에서도 성능 손실을 크게 줄일 수 있다.

AWQ는 `Activation-aware Weight Quantization`의 약자다. 이름 그대로 activation 통계를 이용하지만, 실제로 낮추는 것은 activation이 아니라 **weight precision**이다. 즉 AWQ는 LLM을 위한 low-bit `weight-only quantization` 방법이다.

한 줄로 요약하면 이렇다.

> AWQ는 activation magnitude로 중요한 weight channel을 찾고, mixed precision 대신 per-channel scaling으로 그 channel의 quantization error를 줄이는 PTQ 알고리즘이다.

![AWQ overview]({{ '/assets/images/blog/awq-paper-figure.png' | relative_url }})

*AWQ는 LLM/VLM을 4bit weight로 압축하고, TinyChat 같은 inference system과 결합해 edge device에서도 실행 가능하게 만드는 것을 목표로 한다.*

## 1. 왜 AWQ가 필요한가

LLM inference에서 가장 큰 병목 중 하나는 memory다. 모델이 커질수록 weight를 GPU memory에 올리는 것 자체가 어려워지고, token generation 단계에서는 weight를 계속 읽어야 하므로 memory bandwidth가 속도를 제한한다.

예를 들어 175B parameter 모델을 FP16으로 저장하면 weight만 약 350GB가 필요하다. GPU 여러 장을 쓰지 않으면 올리기 어렵고, edge device에서는 더더욱 불가능하다.

그래서 weight quantization이 중요해진다.

```text
FP16 weight:
16bit per weight

INT4 weight:
4bit per weight
대략 4배 작은 weight 저장량

INT3 weight:
3bit per weight
더 작은 저장량, 하지만 정확도 손실 위험 증가
```

하지만 단순히 weight를 가장 가까운 quantization level로 반올림하는 `RTN(round-to-nearest)`은 낮은 bit에서 성능이 크게 무너질 수 있다. GPTQ처럼 reconstruction 기반으로 보정하는 방법도 있지만, AWQ는 다른 방향을 택한다.

AWQ의 질문은 이것이다.

```text
모든 weight를 똑같이 양자화해야 할까?
정말 중요한 weight만 더 잘 보호할 수는 없을까?
```

## 2. 중요한 weight는 activation이 알려준다

AWQ의 첫 번째 관찰은 **LLM의 weight 중 일부만 매우 중요하다**는 것이다.

논문은 OPT 모델을 INT3-g128로 양자화하면서 일부 channel만 FP16으로 남기는 실험을 한다. 결과는 꽤 강하다. activation 기준으로 0.1%-1% channel만 보호해도 perplexity가 크게 좋아진다.

![AWQ salient table]({{ '/assets/images/blog/awq-salient-table.png' | relative_url }})

*activation 기준으로 선택한 channel을 FP16으로 남기면 RTN 대비 perplexity가 크게 개선된다. 반면 weight magnitude 기준이나 random selection은 효과가 작다.*

여기서 중요한 점은 어떤 weight가 중요한지 판단할 때 weight 자체의 크기를 보면 안 된다는 것이다.

```text
weight magnitude가 큰 channel
-> 반드시 중요한 것은 아님

activation magnitude가 큰 channel과 연결된 weight
-> 모델 출력에 더 큰 영향을 줄 가능성이 높음
```

직관적으로 생각하면 자연스럽다.

어떤 input feature가 자주 크고 강하게 활성화된다면, 그 feature와 연결된 weight는 output에 자주 큰 영향을 준다. 반대로 weight 값이 커 보여도 실제 activation이 거의 작다면 모델 출력에 미치는 영향은 제한적일 수 있다.

그래서 AWQ는 weight-only quantization 방법이지만, 중요한 weight channel을 찾을 때는 activation 통계를 본다.

## 3. Mixed Precision은 좋지만 하드웨어 친화적이지 않다

가장 단순한 보호 방법은 중요한 weight channel만 FP16으로 남기는 것이다.

```text
대부분 weight:
INT3 또는 INT4

중요한 0.1%-1% weight:
FP16 유지
```

정확도만 보면 이 방법은 효과가 있다. 하지만 실제 inference system에서는 다루기 까다롭다. 같은 matrix 안에 INT4와 FP16이 섞이면 kernel 구현, memory layout, packing, vectorized load가 복잡해진다.

즉 mixed precision은 알고리즘적으로는 좋아 보이지만, hardware efficiency 관점에서는 좋지 않다.

AWQ의 핵심은 여기서 나온다.

> 중요한 weight를 실제로 FP16으로 남기지 말고, quantization 전에 scaling해서 quantization error를 줄이자.

## 4. Activation-aware Scaling

AWQ는 중요한 channel을 보호하기 위해 per-channel scaling을 사용한다.

linear layer를 단순하게 쓰면 다음과 같다.

$$
y = Wx
$$

어떤 input channel에 대해 weight를 $s$배 키우고 activation을 $1/s$배 줄이면 전체 계산은 그대로다.

$$
y = W x = (W \cdot s)(x / s)
$$

즉 수학적으로는 같은 함수를 유지하면서, quantization 전에 특정 weight channel의 scale을 키울 수 있다.

왜 이게 도움이 될까?

quantization에서는 작은 값이 low-bit grid에 눌리면서 상대 오차가 커질 수 있다. 중요한 channel의 weight를 미리 키우면, 그 channel은 quantization grid에서 더 잘 표현될 가능성이 높아진다. 이후 activation 쪽에서 inverse scaling을 하면 전체 layer의 의미는 유지된다.

![AWQ salient scaling]({{ '/assets/images/blog/awq-salient-scaling.png' | relative_url }})

*중요한 weight를 FP16으로 남기면 정확도는 좋아지지만 mixed precision은 비효율적이다. AWQ는 activation-aware scaling으로 같은 목적을 더 hardware-friendly하게 달성한다.*

다만 scale을 무작정 키우면 안 된다. 중요한 channel은 보호되지만, 같은 group 안의 다른 weight들의 상대 오차가 커질 수 있기 때문이다.

그래서 AWQ는 activation 평균 크기를 이용해 scale 후보를 만들고, 작은 grid search로 layer output 차이가 가장 작은 scale을 찾는다.

논문에서 scale search의 직관은 다음과 같다.

```text
activation magnitude가 큰 channel
-> 더 중요한 channel로 본다
-> 더 크게 scaling해서 quantization error를 줄인다

activation magnitude가 작은 channel
-> 과하게 보호하지 않는다
-> 전체 quantization error 균형을 맞춘다
```

AWQ는 이 과정에서 backpropagation이나 reconstruction을 하지 않는다. calibration set을 조금 사용해 activation statistics를 모으고, per-channel scale과 clipping range를 찾는다.

이 점이 GPTQ와의 큰 차이다.

## 5. GPTQ와 무엇이 다른가

GPTQ도 post-training quantization이고, LLM을 3-4bit로 줄이기 위한 강력한 방법이다. 하지만 접근 방식은 다르다.

| 항목 | GPTQ | AWQ |
|---|---|---|
| 핵심 정보 | Hessian / input covariance | activation magnitude |
| 방식 | layer output reconstruction | salient channel scaling |
| 보정 | inverse Hessian 기반 error compensation | per-channel scale search |
| 학습/역전파 | 없음 | 없음 |
| calibration 민감도 | reconstruction 때문에 민감할 수 있음 | activation 통계 중심이라 비교적 강함 |
| 시스템 관점 | 정확한 quantization에 초점 | hardware-friendly quantization과 serving까지 연결 |

GPTQ는 "양자화된 layer output이 원래 output과 최대한 비슷하도록 weight를 보정하자"에 가깝다.

AWQ는 "모든 weight가 같은 중요도를 갖지 않으니, activation이 알려주는 중요한 channel을 더 잘 보존하자"에 가깝다.

둘 다 좋은 방법이지만, AWQ는 reconstruction을 하지 않기 때문에 calibration set에 덜 과적합되고, instruction-tuned model이나 multi-modal model에도 잘 일반화된다는 점을 강조한다.

## 6. TinyChat: 알고리즘을 실제 속도로 연결하기

양자화 논문에서 자주 생기는 함정이 있다.

```text
이론적으로 weight는 4배 줄었다.
그런데 실제 inference는 별로 빨라지지 않는다.
```

그 이유는 kernel, memory layout, dequantization overhead, kernel launch overhead 때문이다. weight를 INT4로 저장해도 매번 unpacking과 dequantization이 비효율적으로 일어나면 실제 속도 이득이 줄어든다.

AWQ 논문은 이 문제를 TinyChat이라는 inference system으로 함께 다룬다.

![AWQ generation bottleneck]({{ '/assets/images/blog/awq-generation-bottleneck.png' | relative_url }})

*LLM generation 단계는 memory bandwidth에 묶이기 쉽다. weight-only quantization은 weight loading 비용을 줄여 이 병목을 완화한다.*

TinyChat의 핵심은 다음과 같다.

- W4A16 방식으로 weight는 4bit, activation은 FP16으로 둔다.
- kernel fusion으로 intermediate DRAM access와 kernel launch overhead를 줄인다.
- platform-aware weight packing으로 INT4 weight load와 unpacking을 효율화한다.
- desktop GPU뿐 아니라 Jetson Orin 같은 edge GPU에서도 실행을 목표로 한다.

논문은 TinyChat이 HuggingFace FP16 구현 대비 desktop/mobile GPU에서 평균 3배 이상 speedup을 보였다고 보고한다. 또한 Jetson Orin 64GB에서 Llama-2-70B를 단일 device에 올리는 사례도 보여준다.

이 지점에서 AWQ는 단순한 quantization algorithm이 아니라, **LLM을 실제 device에서 돌리기 위한 compression + serving stack**에 가깝다.

## 7. 실험 결과

논문은 LLaMA, Llama-2, OPT, Vicuna, OpenFlamingo, LLaVA 등 다양한 모델에서 AWQ를 평가한다. 기본 설정은 주로 grouped weight-only quantization이며, group size는 128을 사용한다.

LLaMA/Llama-2 결과를 보면 AWQ는 RTN, GPTQ, GPTQ-Reorder보다 낮은 perplexity를 보이는 경우가 많다.

![AWQ LLaMA results]({{ '/assets/images/blog/awq-llama-results.png' | relative_url }})

*LLaMA와 Llama-2에서 AWQ는 INT3/INT4-g128 조건 모두에서 RTN과 GPTQ 계열보다 좋은 perplexity를 보인다.*

예를 들어 Llama-2 7B의 INT4-g128 결과를 보면 다음과 같다.

| 방법 | PPL |
|---|---:|
| FP16 | 5.47 |
| RTN | 5.73 |
| GPTQ | 5.69 |
| GPTQ-R | 5.63 |
| AWQ | 5.60 |

INT3에서는 차이가 더 커진다.

| 방법 | PPL |
|---|---:|
| FP16 | 5.47 |
| RTN | 6.66 |
| GPTQ | 6.43 |
| GPTQ-R | 6.42 |
| AWQ | 6.24 |

multi-modal model에서도 결과가 좋다. OpenFlamingo-9B COCO captioning에서 INT4-g128 32-shot 기준으로 FP16 대비 성능 저하는 다음과 같다.

| 방법 | 32-shot CIDEr 하락 |
|---|---:|
| RTN | -4.57 |
| GPTQ | -6.72 |
| AWQ | -1.17 |

이 결과는 AWQ의 장점이 language modeling perplexity에만 갇히지 않는다는 것을 보여준다. activation 통계 기반 scaling이 calibration domain에 덜 묶이기 때문에, instruction-tuned model이나 VLM에도 비교적 잘 적용된다.

## 8. AWQ의 장점

AWQ의 장점은 크게 네 가지다.

첫째, 단순하다. Hessian inverse나 layer reconstruction 없이 activation scale 통계와 grid search만으로 동작한다.

둘째, hardware-friendly하다. 중요한 weight를 FP16으로 남기는 mixed precision 대신, 모든 weight를 같은 low-bit format으로 유지하면서 channel scaling으로 보호한다.

셋째, calibration set에 덜 민감하다. 논문은 calibration distribution과 evaluation distribution이 달라질 때 GPTQ보다 AWQ의 perplexity 증가가 작다고 보고한다.

넷째, system과 같이 설계되어 있다. TinyChat을 통해 weight-only quantization의 이론적 메모리 절감이 실제 speedup으로 이어지도록 kernel과 packing까지 다룬다.

## 9. 한계와 주의점

AWQ도 만능은 아니다.

첫째, weight-only quantization이므로 activation과 KV cache 문제를 모두 해결하지는 않는다. 긴 context serving에서는 KV cache가 큰 병목이 될 수 있다.

둘째, activation statistics가 필요하다. reconstruction은 하지 않지만, calibration data를 완전히 없앨 수는 없다.

셋째, group quantization 설정에 영향을 받는다. group size, bit width, clipping, scale search 범위에 따라 품질과 속도 trade-off가 달라진다.

넷째, perplexity가 좋다고 모든 downstream behavior가 보장되는 것은 아니다. reasoning, safety, factuality, tool use 같은 능력은 별도로 평가해야 한다.

다섯째, 실제 speedup은 kernel 구현에 크게 의존한다. 같은 AWQ weight라도 runtime이 INT4 GEMM, dequantization, packing을 얼마나 잘 처리하느냐에 따라 체감 속도가 달라진다.

## 내가 이해한 핵심

AWQ의 핵심은 다음과 같다.

```text
LLM weight는 모두 똑같이 중요하지 않다.
중요한 channel은 weight magnitude보다 activation magnitude로 더 잘 찾을 수 있다.
중요한 weight를 FP16으로 남기면 정확도는 좋아지지만 하드웨어 효율이 나쁘다.
AWQ는 per-channel scaling으로 중요한 channel의 quantization error를 줄인다.
backpropagation이나 reconstruction 없이 calibration activation 통계만 사용한다.
TinyChat은 AWQ weight를 실제 inference speedup으로 연결한다.
```

GPTQ가 "layer output reconstruction을 통해 quantization error를 보정하는 방법"이라면, AWQ는 "activation이 알려주는 중요한 channel을 scaling으로 보호하는 방법"이다.

그래서 AWQ는 단순한 압축 기법이라기보다, LLM을 local device와 edge GPU에서 실행하기 위한 실용적인 quantization 설계로 볼 수 있다.

## 한 줄 요약

AWQ는 activation magnitude로 중요한 weight channel을 찾고, per-channel scaling으로 그 channel을 보호해 3-4bit weight-only quantization의 정확도와 하드웨어 효율을 함께 잡는 방법이다.
